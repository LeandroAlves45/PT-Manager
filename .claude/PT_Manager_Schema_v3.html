PT Manager — Schema da Base de Dados

28 tabelas da aplicação + __EFMigrationsHistory, total 29, PostgreSQL 16 (Neon), modeladas para EF Core 10. IDs em uuid nativo gerados na aplicação (Guid.NewGuid()), multi-tenancy via raízes com owner_trainer_id e filhas ligadas à raiz, timestamps sempre TIMESTAMPTZ, migrations geradas com dotnet ef migrations add — nunca escritas à mão.

Os Global Query Filters são centralizados no PtManagerDbContext, exigem tenant presente e usam navegações para proteger também queries diretas às entidades filhas. Estão ligados a ITenantContext, nunca a HttpContext. Roles: superuser, trainer, client.

Identidade & Auth

Tabela users própria com stores customizados do ASP.NET Core Identity (Decisão 2 — não o schema AspNet* padrão). Refresh tokens com rotação, deteção de reuso e revogação de família; convites de uso único. Só hashes de tokens são persistidos.

ENTIDADE users
Utilizadores (trainer/client/superuser) com as colunas mínimas exigidas pelas interfaces do Identity efetivamente usadas (hashing, lockout, verificação de email).
id uuid PK
email varchar(255) not null
normalized_email varchar(255) not null unique
Uppercase invariante, para lookups do Identity
password_hash varchar(255) not null
security_stamp varchar(255) not null
concurrency_stamp varchar(255) not null
full_name varchar(255) null
role varchar(50) not null default 'trainer'
CHECK: 'trainer' | 'client' | 'superuser'
email_confirmed boolean default false
lockout_end timestamptz null
access_failed_count integer default 0
is_active boolean default true
is_deleted boolean default false
created_at / updated_at timestamptz not null
ENTIDADE refresh_tokens
Substitui o active_tokens do Python. Rotação com deteção de reuso: token com revoked_at preenchido reutilizado ⇒ revogar toda a family_id.
id uuid PK
user_id uuid FK → users ON DELETE CASCADE
family_id uuid not null
Agrupa a cadeia de rotação de uma sessão de login
token_hash varchar(255) not null unique
Nunca o valor em claro
rotated_from_id uuid FK null → refresh_tokens ON DELETE SET NULL
expires_at timestamptz not null
revoked_at timestamptz null
created_at timestamptz not null
ENTIDADE invite_tokens
Convites de trainers a futuros clientes. Uso único, com expiração.
id uuid PK
trainer_id uuid FK → users ON DELETE CASCADE
email varchar(255) not null
token_hash varchar(255) not null unique
expires_at timestamptz not null
is_used boolean default false
created_at timestamptz not null
Roles: superuser (admin global), trainer (dono do tenant), client (cliente do trainer). Sem tabelas de roles — coluna única com CHECK.

Jobs & Outbox

Substituem RabbitMQ/MassTransit no MVP: fila durável em Postgres processada por um dispatcher interno ativado pelo Upstash QStash (de 20 em 20 minutos), e Outbox pattern para efeitos transacionais (ex.: email pós-pagamento Stripe).

ENTIDADE durable_jobs
Fila de jobs. Claim transacional com SELECT FOR UPDATE SKIP LOCKED e token opaco novo por claim. Renovação, conclusão e falha exigem lease ativo.
id uuid PK
trainer_id uuid FK null → users ON DELETE CASCADE
NULL quando o job não é tenant-owned
job_type varchar(100) not null
'send_notification', 'process_billing', etc.
job_version integer not null default 1
payload jsonb not null
status varchar(50) not null default 'pending'
scheduled_at timestamptz not null
attempts integer not null default 0
next_attempt_at / lease_expires_at timestamptz null
lease_owner_id uuid null
Token opaco da execução de claim
idempotency_key varchar(255) not null unique
correlation_id uuid not null
last_error text null
Sanitizada — nunca stack trace completo
created_at / updated_at timestamptz not null
ENTIDADE outbox_messages
Outbox recuperável. CHECK status: pending | processing | completed | failed | dead_letter.
id uuid PK
trainer_id uuid FK null → users ON DELETE CASCADE

'payment_confirmed_email', 'payment_failed_alert', etc.
payload jsonb not null

idempotency_key varchar(255) not null unique
attempts integer not null default 0

Fluxo: Alteração de domínio + OutboxMessage (mesma transação) → QStash acorda o dispatcher → claim curto com SELECT FOR UPDATE SKIP LOCKED → efeito executado → conclusão condicional. Entrega at-least-once — handlers idempotentes via idempotency_key.
